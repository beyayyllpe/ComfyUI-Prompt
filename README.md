# ComfyUI-Prompt

> 面向中文用户的 ComfyUI 提示词工具集：用大模型把中文描述翻译 / 扩写成适合各类底模的提示词，支持多图逆推、图像编辑指令和视频提示词，零依赖、配置全在 JSON 里。

---

## 功能特色

**按底模架构输出，不用自己懂提示词格式**
选择你要用的底模类型，节点会输出最适合它的格式：中文自然语言（Z-Image / Qwen-Image）、英文句子（Krea 2 / FLUX）、英文标签（SDXL / Pony / Illustrious）。

**扩写程度可调**
从"只翻译不扩写"到"详细扩写"共四档，扩写时紧扣原意，把"优雅""电影感"这类抽象词转成具体的服装、光线、镜头描述。

**图像逆推 + 多图融合 + 编辑指令**
最多接入 10 张图片，接口随连线自动增加。可以逆推单张图的提示词，也可以"用图1的人物、图2的服装、图3的场景"融合成一段提示词，还能为 Qwen-Image-Edit、FLUX Kontext 等编辑模型生成精确的改图指令。

**多家服务商，配置全在 JSON**
内置 DeepSeek、通义千问、Gemini、OpenAI、Claude，以及腾讯、百度官方机器翻译。任何 OpenAI 兼容接口（硅基流动、智谱、Kimi、OpenRouter 等）都能在 JSON 里添加，下拉框自动出现，无需改代码。

**为国内用户设计**
国内服务商强制直连，不走代理、不耗机场流量；全中文界面，复杂参数有悬浮说明；推荐模型下线时自动切换可用模型。

**AI 指令完全可改**
所有系统指令都在 `ai_prompt_templates.json` 里，改完保存即生效，**无需重启 ComfyUI**。模板带版本号，插件更新时只覆盖版本号变了的条目，你改过的保持原样。

**视频提示词：不懂镜头也能写**
你只管用大白话说要什么，景别、运镜、光线、节奏、声景的专业判断交给 AI——但**判断规则是写死在指令里的，不是放任它发挥**。
五个拍摄开关（分镜 / 运镜 / 光线 / 表情 / 声音）默认全是「交给AI」，想干预时才去拨；拨了就是硬命令，AI 不许改。
设置不合理时直接算出具体数字提醒你（「15 秒切 10 个镜头，平均每镜 1.5 秒，人脸基本每镜都会变样」），不用学任何新概念。
支持文生 / 首帧 / 首尾帧 / 尾帧 / 参考素材**五种模式**，按接入的图片自动判断。参考图最多 9 张，动态输入口。
输出两路：**提示词**直接接视频模型，**中文说明**里有镜头清单、完整对照译文、AI 补了什么、以及需要注意的地方。
内置 6 种风格预设，提炼自 MiniMax 官方风格技能；目标模型（H3、WAN2.2 等）规范同样由 JSON 驱动，加一段就多一个选项。

**零依赖**
只使用 Python 标准库和 ComfyUI 自带的库，不需要 `pip install` 任何东西，不会和其他插件冲突。

**完整日志**
每次调用在命令行打印完整流程：服务商、模型、设置、耗时、token 用量、结果；出错时附带中文解决建议。

## 安装

### 方式一：Git 克隆（推荐）

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/beyayyllpe/ComfyUI-Prompt.git
```

### 方式二：手动下载

在本页点击 **Code → Download ZIP**，解压后把文件夹放到 `ComfyUI/custom_nodes/` 下，文件夹名改为 `ComfyUI-Prompt`。

> 注意：解压后常会多套一层文件夹。正确的结构是 `custom_nodes/ComfyUI-Prompt/__init__.py`，而不是 `custom_nodes/ComfyUI-Prompt/ComfyUI-Prompt/__init__.py`。

首次启动会在插件目录自动生成两个文件：`ai_prompt_keys.json`（填 Key）和 `ai_prompt_templates.json`（AI 指令模板）。

### 环境要求

- ComfyUI 较新版本（视频节点使用 V3 schema，需要 2026 年以后的版本）
- 无需额外 Python 依赖
- 使用 Gemini / OpenAI / Claude 等海外服务需要能访问外网

## 配置 API Key

用记事本（推荐 VS Code 或 Notepad++）打开插件目录下的 `ai_prompt_keys.json`，把 Key 填进对应位置：

```json
{
  "DeepSeek": "sk-xxxxxxxx",
  "通义千问": "",
  "Gemini": "AIzaSy-xxxxxxxx",
  "OpenAI": "",
  "Claude": "",
  "腾讯翻译_SecretId": "",
  "腾讯翻译_SecretKey": "",
  "百度翻译_APPID": "",
  "百度翻译_密钥": "",
  "自定义服务商": { }
}
```

用不到的留空即可。保存后**重启 ComfyUI**。

Key 的读取顺序：节点上的"API密钥"参数 → `ai_prompt_keys.json` → 系统环境变量（`DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`、`GEMINI_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 等）。

> ⚠️ **不要把 Key 填在节点上。** ComfyUI 会把整个工作流写进出图 PNG 的元数据，分享图片就等于分享了你的 Key。节点上的"API密钥"只适合临时测试，也不会自动保存。

## 使用说明：提示词翻译

### 常显参数

| 参数 | 作用 |
|---|---|
| 文本 | 输入描述或编辑意图，可用"图1""图2"引用接入的图片。只接一张图时可留空 |
| 目标格式 | 按你要用的底模选择，见下表 |
| 扩写程度 | 不扩写 / 简洁 / 适中 / 详细 |
| 服务商 | 下拉框内容来自 `ai_prompt_keys.json` |
| 🔄 获取模型列表 | 查询当前 Key 可用的模型，弹出可搜索的列表 |
| 模型 | 留空 = 推荐模型 |
| 创意度 | 扩写的发散程度，建议 0.5~0.8。翻译、看图、编辑模式会自动使用低数值 |
| 每次运行 | 固定：内容不变时复用上次结果，不重复扣费；随机：每次重新生成 |

### 目标格式

| 选项 | 适用底模 | 输出 |
|---|---|---|
| 中文（Qwen/ZIT/通用） | Z-Image、Qwen-Image、可图、混元、Wan | 中文自然语言 |
| 英文句子（Krea2/FLUX） | Krea 2、FLUX.2 | 英文自然语言句子 |
| 英文标签（SDXL/Pony） | SDXL、Pony、Illustrious | 英文逗号标签 |
| 编辑指令（英文） | Qwen-Image-Edit、FLUX Kontext | 英文改图指令 |
| 编辑指令（中文） | Qwen-Image-Edit | 中文改图指令 |
| 负面词（英文） | 所有（仅 CFG > 1 时有效） | 英文负面提示词 |
| 不处理 | — | 原样输出，不调用 API |

> ⚠️ SDXL 系列的 CLIP 文本编码器**看不懂中文**，给 SDXL 用一定要选"英文标签"。

### 扩写程度

三档控制的是**五层各挖多深**，不是简洁档砍掉几层：

| | 拍摄 | 主体 | 环境 | 光线 | 风格 |
|---|---|---|---|---|---|
| **简洁** | 景别 + 机位 | 最关键 2~3 项 | 一句话说清在哪 | 方向 + 冷暖 | 一个词 |
| **适中** | 加具体焦段 + 景深 | 主要维度都写到 | 场所 + 时间 + 空间层次 | 加光源类型 + 软硬 | 加色彩处理 |
| **详细** | 加光圈、快门、位置与留白 | 深入到材质、纹样、细部 | 前中后景分层 | 加光比 + 投影落在哪 | 加颗粒、锐度、气氛 |

对应篇幅（按最终输出的格式走，不是一个数字套所有格式）：

| 档位 | 中文 | 英文句子 | 英文标签 |
|---|---|---|---|
| 简洁 | 60~100 字 | 60~90 词 | 25~32 词 |
| 适中 | 150~250 字 | 160~230 词 | 38~45 词 |
| 详细 | 300~450 字 | 300~420 词 | 45~52 词 |

英文句子只给词数、不给句数。句子长短由内容决定，为了凑句数把一句劈成三句并不会多出信息。

> **标签格式为什么比句子短这么多**
>
> SDXL 的 CLIP 编码器每 77 个 token 切一段，**每段单独编码一次，段与段之间互相看不见**。实测一个英文词约合 1.37 个 token，所以 50 个词 ≈ 70 token，刚好在一段之内。
>
> 写超了有两个后果。一是切到第二段往后的词模型基本不执行，字数白花。二是更麻烦的——**修饰语会和被修饰的词被切开**：假如 `deep burgundy` 落在第一段末尾、`satin slip dress` 被切到第二段开头，这两组词在编码时永远碰不上面，模型就不知道是谁 burgundy。这是属性串位最常见的成因。
>
> 所以标签档压到 50 个词**不是少写内容**，是让写下的每个词都真的生效。标签的信息密度本来就比散文高三倍：「身穿亮面漆皮炭黑挂脖背心」二十个字，写成 `black patent leather halter top` 只要五个词。
>
> 也因此，标签格式下**详细档和适中档只差几个词，区别在取舍不在长度**：详细档把 50 个词全花在画面上，适中档留出余量给你自己加 LoRA 触发词和质量词。超额时按优先级砍，先保「数量 → 风格 → 景别 → 服装材质 → 环境 → 光线 → 质感」，从纹样细部、远景陈设、投影落点、光比、构图法这些砍起。
>
> **你自己写死的内容不参与压缩。** 写死 15 个词，AI 自己补的部分就只剩 35 个词的额度。
>
> 这条限制只对 SDXL 系（含 Pony、Illustrious、NoobAI）成立。Qwen-Image、FLUX 用的是长文本编码器，没有 77 这面墙——要喂它们请选「英文句子」或「中文」，那两档不压缩。

**「不扩写」档**只翻译整理，不增加内容，长度跟着你的输入走。

看图和编辑模式下，扩写程度控制的是**描述有多细**，不会脑补图片里没有的内容。

**图像逆推用的是同一套篇幅数字**（上面那张表），标签格式同样受 77 token 上限约束——逆推一张信息量很大的图时，AI 会按同一张砍词优先级表取舍，而不是把一百多个标签全堆上去。编辑指令模式输出的是改图指令、不是 SD 提示词，不受这个限制，所以只分中英文两个长度。

### 一张图的五层结构

扩写时 AI 按这五层组织画面，而不是套一条写死的顺序：

| 层 | 写什么 |
|---|---|
| **拍摄** | 媒介、景别、机位高度与方位、焦段、光圈景深、快门、主体在画面里的位置与留白 |
| **主体** | **按主体类型走不同的维度** |
| **环境** | 场所、时间天气、陈设、前中后景分层、与主体的关系 |
| **光线** | 光源类型、方向、软硬、光比、色温、投影和高光落在哪 |
| **风格** | 整体风格、色彩处理、画面质感、气氛 |

**主体层会先判断类型再走对应清单**——人物、动物、建筑、静物产品、食物、载具、风景、群像、抽象图形各有各的维度。建筑写的是「年代流派·体量几何·材料风化·开窗节奏·尺度参照」，和人物的「五官·发型·服装·姿态」毫无重叠。

列出的类型和词汇都**只是示例不是菜单**——碰到没列到的主体（机械、昆虫、服装平铺、界面截图……），AI 按同样思路自己定该写哪些维度。

配套的硬要求是**具体到可验证**：光线给方向和色温，不许写「合适的焦段」这种废话。

#### 开头第一句定调

五层之前，第一句先把四件事交代完（约 20~30 字）：

**这是什么图**（媒介风格）→ **画的是什么**（可数主体写明数量）→ **在哪** → **处于什么状态**

```
人像：写实时尚人像摄影，一名二十出头的亚裔女子在城市街头起舞
建筑：建筑摄影，一座清水混凝土美术馆立在缓坡草坡上，正午
静物：静物摄影，三只手工陶杯摆在木案上，窗光斜照
```

主体出现得越晚，模型抓住它的可能性越低。这条对文生图扩写、图像逆推、三种输出格式一律适用。

#### 器材参数写效果，不写数字

模型没有真的镜头，`f/2.8` 这类数字它执行不了，但「浅景深、背景化开」能执行：

| 不要写 | 写成 |
|---|---|
| f/2.8、f/1.4 | 浅景深、背景虚化、bokeh |
| 1/1000s、1/15s | 动作定格清晰 / 拖影 |
| 三分法、黄金分割 | 主体偏右、左侧留出街道作为留白 |
| 横构图、竖构图 | 不写——画幅由生成节点的宽高决定 |

焦段是例外，`85mm 中长焦` 这种说法模型认，但要连带写出画面特征（背景压缩、透视平直）。

#### 多个主体时的锚定规则

一张图里两个人以上，属性最容易互相串。四条规则：

1. 每个主体**独立成句**，不要把两个人塞进一句
2. 一个主体的全部属性**连续写完**再写下一个
3. 关键属性在该主体的句子里**重复一次**
4. **不要在分述前先写共有属性**（「两人都穿西装，一个打红领带一个打蓝领带」——红蓝一定会串）

人多就写长，每个主体仍要写满该类型的全部维度，不能因为人多就每人只给一个词。

> **⚠ 但这套规则在 SDXL 上有天花板**
>
> CLIP 文本编码器没有指代绑定能力——它不理解「左边那个穿红的」里「红」属于谁。四个人各穿各的衣服，这在 SDXL 上是**架构性做不到**，和提示词怎么写无关。
>
> 真要多主体差异化，换 Qwen-Image 或 FLUX（文本编码器不同），或者上区域提示词、ControlNet、分区重绘。提示词工程到此为止。

### 图像输入（最多 10 张）

新建节点时只有"图像1"，接上后自动出现"图像2"，依次增加到最多 10 个；断开后多余的空接口会自动收回。发给 AI 时每张图标注为"图N"，**编号与输入口一致**（只接了图像1 和图像3，AI 看到的就是图1、图3）。

**三种用法：**

**单图逆推**：接图像1，文本留空，目标格式按底模选。

**多图融合**：接多张图，文本写"用图1的人物，穿图2的服装，放在图3的场景里"，输出一段统一画面的提示词。未指定分工时以图1为主体。

**编辑指令**：目标格式选"编辑指令"，文本写意图，例如"让图2的女孩穿上图1的衣服"。输出会具体描述要迁移的元素，并写明需要保持不变的部分。

AI 在动笔前会先按固定顺序把每张图读一遍：

```
整体 → 拍摄（景别·机位·景深，迁移进来的元素必须匹配这几项）
     → 主体【从上到下逐部位】（头发→面部→颈肩→上身→腰胯→下身→手脚）
     → 细部（材质·纹样·新旧·配饰·文字）
     → 环境【从远到近】（背景→中景→前景，含阴影遮挡反射）
     → 光线（方向·软硬·色温，高光阴影落在哪）
```

这样写出来的指令会具体到部位——不是「图1的衣服」，而是「图1中那件米白色蕾丝镶边吊带，肩带细、裙摆到膝上」。

所有档位都会要求**融合对得上**：光线方向、色温、透视、比例、景深要和目标图一致，接缝处不能出现两套光。

> ⚠ 编辑指令模式**没接图片时会直接报错**。没有图的话 AI 只能凭空编造「图1」「图2」里有什么，写出来看着像真的，实际和你的图毫无关系。最常见的原因是「加载图像」节点被 Bypass 了。

> 看图需要服务商支持视觉能力，选错会在调用前直接提示，不浪费额度。
> Qwen-Image-Edit 本身最多接 3 张图，编辑指令中提到的图应与编辑模型实际接入的图一致。
> 每张图大约消耗 1000 token 左右，图越多费用越高。

### 高级参数（点"显示高级输入"展开）

| 参数 | 作用 |
|---|---|
| 思考模式 | 让 AI 先推理再回答。复杂要求更不易遗漏，但更慢更贵，平时建议关闭 |
| 风格方向 | 给画面定调，如"胶片摄影""日系清新""赛博朋克" |
| 开头固定文字 | 不经过 AI，原样放在最前面，适合 LoRA 触发词、`<sks>` |
| 结尾固定文字 | 不经过 AI，原样放在最后面 |
| 给AI的额外要求 | 追加规则，如"人物是亚洲面孔""不要出现文字" |
| API密钥 | 临时填写 Key（不推荐，见上文） |
| 代理地址 | 海外服务商使用的本地代理端口，如 `127.0.0.1:7890`。留空则使用系统代理 |
| 自定义指令 | 完全替换本次的系统指令，临时试验用 |
| 详细日志 | 额外打印系统指令全文、请求参数、API 原始返回 |

## 使用说明：视频提示词

用大白话写想要什么，AI 替你做完景别、运镜、光线、节奏、声景的专业决策，并输出一段中文说明告诉你它设计了什么、为什么这么设计。

### 常显参数

| 参数 | 作用 |
|---|---|
| 你的想法 | 大白话写要什么，例如「女人站在天台看夜景，有点孤独」 |
| 目标模型 | H3（海螺3）/ WAN2.2 / 通用。内容来自 JSON，可自行添加 |
| 视频时长 | 秒。H3 支持 4~15 秒 |
| 分镜 | `0` = 交给AI，`1~10` = 指定几个镜头 |
| 运镜 | 交给AI / 镜头不动 / 跟着主体 / 推近 / 拉远 / 环绕 |
| 光线 | 交给AI / 保持不变 / 变亮 / 变暗 / 换色调 |
| 表情 | 交给AI / 保持不变 / 允许变化 |
| 声音 | 静音 / 环境音 / 环境音+动作音 / 再加配乐 |
| 风格预设 | 6 种，见下 |
| 服务商 / 模型 | 调用哪家 AI 来写提示词。接了图时需要支持看图的型号 |
| 创意度 | 保守 / 平衡 / 大胆。接了图片时自动压到保守 |
| 每次运行 | 固定 / 随机 / **直通** |

### 「交给AI」不是放任不管

五个开关默认全是「交给AI」，但判断规则是写死在指令里的：

| 开关 | AI 的判断依据 |
|---|---|
| 分镜 | 有没有必要换视角——要看清一个表情、交代一个新的空间关系、推节奏，才值得切一刀。只是远近或角度略变就用运镜，不要切。为了"不单调"而切是最糟的理由 |
| 运镜 | 人不动靠表情传情绪 → 固定机位；人在移动 → 跟随；从环境进内心 → 推近；从人物退回处境 → 拉远。**铁律：默认不动，运动要挣来** |
| 光线 | 光变必须有光源上的解释（开灯、车灯扫过、云遮日、走进阴影）。"情绪到了所以光变暖"不成立。找不到来源就全程不变 |
| 表情 | 情绪转变要压在画面里的触发点后面半拍。找不到触发点就让情绪在一个基调里细微起伏，不硬转 |
| 台词 | 留空时 AI 自己判断要不要有人说话：有交流对象、时间够说完（中文一秒约 3~4 字）、镜头看得见嘴，三条都满足才写 |

想干预就拨开关，拨了就是硬命令，AI 不许改。

### 稳定性提醒

设置不合理时，节点直接把算出来的数字摆给你看，写在中文说明里：

```
· 15 秒切 10 个镜头，平均每镜 1.5 秒。镜头短于 2 秒时人脸和服装细节
  容易在切口处变样，降到 7 镜会稳不少。
· 同时开了：切镜头、跟着主体、光线和表情变化。三件事叠在一起，
  模型要同时对齐位移和状态变化，崩坏概率明显上升。
```

### 五种模式（按接入的图片自动判断）

| 接入 | 模式 | 说明 |
|---|---|---|
| 都不接 | 文生视频 | |
| 只接首帧图 | 首帧生视频 | 先读懂画面再设计运动，不改人物长相和服装 |
| 首帧 + 尾帧 | 首尾帧生视频 | 描述从起点到终点的连续变化路径。官方推荐单镜头，「分镜」填 0 时按 1 镜处理，想多镜头直接填数字 |
| 只接尾帧图 | 尾帧生视频 | 设计开头并收敛到该画面。镜头数可以交给 AI |
| 参考图（最多 9 张） | 参考素材生视频 | 把多张图的人、衣服、场景融合成一段视频 |

> 参考图和首帧/尾帧**互斥**，这是官方规定（Ref2VA 和 I2VA 是两套不同的模式），接错了会直接拦下。

### 输出

**提示词**接给视频模型，语言按目标模型的规范（H3 英文、WAN2.2 中文）。

H3 的提示词按官方格式组织。首帧 / 尾帧 / 首尾帧 / 文生四种模式用**三字段**：

| 字段 | 写什么 |
|---|---|
| `integrated_multimodal_description` | 正文。按播放顺序逐镜头写画面、动作、运镜、声音、台词 |
| `overall_soundscape` | 环境音和动作音，1~4 句 |
| `non_diegetic_music` | 画外配乐的配器、速度、节奏、力度变化，1~3 句 |

参考素材模式用**六段**，多出 `subject_definitions`（定义 `<Subject N>` 来自哪张图）、`summary`、`retention_analysis`（每个主体在哪些镜头出现、保留到什么程度）。

镜头写成 `[Shot 1]`（不带时间戳）、`[Shot 2] At 00:03.500, the camera cuts to...`，切点严格递增。
首尾帧和尾帧模式开头还有一行官方固定的图像对齐指令，由节点生成，不经 AI 的手。
尾帧模式把「分镜」填 0 时，节点会等 AI 定好镜头数，再按实际数字补上这一行。

**中文说明**接「预览任意」，里面有四部分：

```
镜头清单
[1] 00:00.000-00:02.500  中景·固定机位    她发现画外目标，表情转为警觉
[2] 00:02.500-00:05.000  中全景·固定机位  跳下车，向前冲刺

（完整对照译文，专业术语后面跟括号用大白话解释）

—— 我替你补了什么 ——
· 运镜：四个镜头都用固定机位，因为舞蹈动作本身已经够丰富……

—— ⚠ 需要注意 ——
· 第4镜只有 2.5 秒，却安排了开枪 + 5 字台词 + 瞄准，动作塞太满
```

### 直通

「每次运行」选 **直通** 时**不调用 AI**，把「你的想法」框里的内容原样当提示词输出。
用于手改提示词后重跑，或复用之前写好的一条，不花调用次数、不上传图片、不需要 Key。

直通时节点仍会帮你做格式自检，结果写在中文说明里：

```
—— ⚠ 需要注意 ——
· 【直通自检】官方字段缺失：overall_soundscape、non_diegetic_music
· 【直通自检】出现了官方格式里没有的写法：[Style]
· 【直通自检】镜头数不符：要求 2 个，实际写出 3 个
```

手改提示词最容易改坏的就是格式，这个检查很实用。

### 高级参数

| 参数 | 作用 |
|---|---|
| 我的具体要求 | 大白话随便写，不用分类（`我要脸的大特写`、`第2个镜头从背后拍她`、`手要一直拿着那把伞`）。你写的每一条都必须被落实，和开关冲突时以你为准 |
| 台词 | 留空＝AI 自己判断要不要有人说话；写了就一定会说，原样不翻译，并启用官方对白规则（说话人 ID、音色设计、口型同步） |
| 不要出现的东西 | 留空＝只用默认那套（不要多余肢体、扭曲的手、水印、画面撕裂）；写了就在默认之上**追加** |
| 思考模式 / API密钥 / 代理地址 / 详细日志 | 同翻译节点 |

### 风格预设

6 种，提炼自 MiniMax 官方风格技能，选中后会注入该风格的质感、运动语言和负面约束：

3D动画（皮克斯风）/ 手绘发光×实拍融合 / 纸艺定格（立体纸偶）/ 纸拼贴（半调编辑风）/ 极简产品广告（苹果风）/ 音乐MV（节拍字幕）

想加新风格，在 `ai_prompt_templates.json` 的「视频风格预设」里照格式加一段，重启后下拉里就有。

## 自定义服务商

任何兼容 OpenAI 格式的接口都可以添加。在 `ai_prompt_keys.json` 的 `自定义服务商` 中加入：

```json
"自定义服务商": {
  "硅基流动": {
    "base": "https://api.siliconflow.cn/v1",
    "model": "Qwen/Qwen2.5-72B-Instruct",
    "key": "sk-xxx",
    "domestic": true,
    "vision": false
  },
  "OpenRouter": {
    "base": "https://openrouter.ai/api/v1",
    "model": "google/gemini-3.8-flash",
    "key": "sk-or-xxx",
    "domestic": false,
    "vision": true
  }
}
```

| 字段 | 说明 |
|---|---|
| base | 接口地址，**必填**，以 `/v1` 结尾，不要带 `/chat/completions` |
| model | 默认模型名 |
| key | API Key |
| domestic | `true`：国内服务，直连不走代理；`false`：走代理 |
| vision | `true`：该模型能看图；`false`：接图时会提示不支持 |

保存后**重启 ComfyUI**，下拉框即出现新服务商。名字以"示例"开头或 `base` 为空的条目会被自动跳过。

**关于 domestic**：它只控制程序层面是否使用系统代理 / 代理地址。如果你使用路由器上的 OpenClash 或 Clash 的 TUN 模式等透明代理，流量走向由代理规则决定，此字段基本不起作用，也不会冲突。

**关于 vision**：内置服务商也可以覆盖默认值。把它改成字典形式即可，无需更新插件：

```json
"DeepSeek": { "key": "sk-xxx", "vision": true }
```

**只修改 Key 或模型名不需要重启**；新增或删除服务商需要重启。

| 视频_大白话翻译 | 把用户的日常说法转成专业表达 |
| 视频_运镜术语表 | 官方 20 种运动类型 + 幅度 + 速度 |
| 视频_镜头规则 | `[Shot N]` 的编号和时间戳写法 |
| 视频_对白 | 说话人 ID、`<d>` 标签、音色设计 |
| 视频_声景守则 / 配乐守则 | 两个声音字段的写法 |
| 视频_画面文字 | 画面上可见文字的写法 |
| 视频模式_* | 五种模式各自的结构要求 |
| 视频_全参考格式 | 参考素材模式的六段式 |
| 视频_锁定要求 | 用户写的要求怎么落实 |
| 视频_负面默认 / 负面写法 | 默认排除项和转写规则 |
| 视频_输出要求 | 输出 JSON 的格式、中文说明的三部分 |
| 视频风格预设 | 6 种风格的约束（嵌套结构） |
| 视频模型规范 | 各目标模型的格式、时长范围、能力（嵌套结构） |

### 注意事项

- 保持 JSON 格式正确：换行写成 `\n`，引号写成 `\"`
- 文件改坏或删除时，自动使用内置默认值，不会报错
- 删除某一条后重启，会自动补回该条的默认值
- **模板带版本号**。插件更新时只有版本号变了的条目会被覆盖成新版，你改过而版本没变的保持原样。升级了哪几个，启动日志会打出来
- 英文模式的指令建议保留 "Output English only"，减少返回中文导致的重试

## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 菜单里没有节点 | 文件夹多套了一层，或加载出错 | 检查目录结构；查看启动日志中 `[CustomNodes]` 的行 |
| 没有找到 xxx 的 API Key | json 未填写或填错位置 | 检查 `ai_prompt_keys.json`，改完重启 |
| HTTP 401 / 403 | Key 错误、失效或服务未开通 | 重新复制 Key |
| HTTP 402 | 余额不足 | 到服务商官网充值 |
| HTTP 404，提到 model | 手填的模型名错误或已下线 | 点"获取模型列表"重选，或清空模型栏 |
| `User location is not supported` | 代理没生效，请求用服务器自己的 IP 直连出去了 | 在节点的"代理地址"里填本地端口。ComfyUI 以服务方式启动时不继承终端的代理变量 |
| `RemoteDisconnected` / `SSL EOF` | 请求体太大走不动代理。**模型列表能刷新就说明网络是通的** | 减少参考图数量，或换国内服务商 |
| 模型返回的内容跟图片对不上 | 用了看不了图的型号 | 节点会检测并拦下。换一个支持看图的型号 |
| 中文说明是空的 | 返回格式不对 | 日志里会写明原因，节点会自动重试 |
| 多次返回中文 | 模型不遵守英文要求 | 换更强的模型，或把创意度调到保守 |
| 点运行结果不变 | "每次运行"为固定 | 改为随机 |
| 编辑指令说需要接入图片 | 图片节点被 Bypass 了，或线没接上 | 取消 Bypass；或把目标格式换成非编辑指令 |
| 老工作流报参数对不上 | 节点输入项变了 | 删掉节点重新拖一个。强行用旧节点会串位 |
| 自定义服务商不出现 | 未重启 / base 为空 / JSON 格式错误 | 检查后重启 |

**费用大概多少？** 以 Gemini 3.8 Flash 为例，一次单图逆推约 1500 token，双图编辑指令约 2500 token，都在人民币一分钱左右。纯文字扩写更便宜。视频提示词因为指令长（近万字），一次约 6000~9000 token。具体价格以各服务商官网为准。本插件不收取任何费用，API 费用由用户自行承担。

**会不会把我的 Key 传出去？** 不会。Key 只保存在本地 json 文件中，仅用于直接请求你选择的服务商。
